# 在真正的 Codex 窗口里加载皮肤

这条路线把本仓库编译出的流体背景和玻璃样式放进 Codex 自己的界面。原来的聊天、侧边栏、输入框仍由 Codex 处理。浏览器预览只用于检查视觉和代码，不能代替桌面接入验收。

2026-10-03 已在 Windows 安装包 `26.930.2377.0` 上完成真实主窗口连接和挂载，WebGL2 渲染正常。输入区保留原生尺寸，启用时与左栏统一为 26px 圆角，关闭后恢复原生 22px。原生设置页提供总开关及“调整皮肤”，关闭时保留入口、停止视觉渲染。[启动与动画验证记录](startup-animation-validation-20261003.json)说明本次实现、自动检查及实际运行范围；[早期验证记录](native-validation-20261003.json)是此前时点的快照，其测试数量及待确认状态不代表本次结果。当前记录未覆盖完整退出再打开的冷启动耗时及全部原生聊天功能。

## 为什么需要明确启动

2026-10-02 只读检查的安装包是 `OpenAI.Codex_26.930.2377.0_x64__2p2nqsd0c76g0`，应用版本 `26.930.21537`，构建 `12776`。正在运行的主进程没有远程调试参数，也没有调试监听端口。生产版本关闭了主界面的 DevTools 菜单。

包内主界面加载的是 `app://-/index.html`，可附带 `initialRoute` 查询参数。原生配色主题的字段只有颜色、字体、对比度及窗口透明开关，没有加载流体脚本的字段。[官方外观文档](https://learn.chatgpt.com/docs/reference/settings)说明了这些原生设置。

运行时二进制包含 Chromium 的 `remote-debugging-port` 开关。与包中依赖版本对应的 [Electron 42.3.0 调试服务源码](https://github.com/electron/electron/blob/v42.3.0/shell/browser/ui/devtools_manager_delegate.cc)使用本机回环监听；[WebContents 源码](https://github.com/electron/electron/blob/v42.3.0/shell/browser/api/electron_api_web_contents.cc)中的 `devTools: false` 限制打开 DevTools。安装包使用定制运行时，不能仅凭这些源码就把真实连接说成已经成功。

Windows 版有单实例锁：已有进程时，再启动一次只会把参数交给旧进程，不会替它打开调试端口。已有同一程序的可用回环调试连接时，启动器直接复用当前窗口；已加载的控制器（包括关闭状态）保持不变。普通启动而没有连接时，需先保存内容、结束正在进行的任务，并正常完全退出 Codex，再使用皮肤入口。脚本不会替用户退出或强制结束它。

## 设置中的开关和桌面入口

加载控制器后，在 Codex 设置页顶部可开启/关闭皮肤，或点“调整皮肤”。关闭恢复原生颜色、背景与圆角，释放流体、玻璃、鲨鱼与网格资源；保留自己的控制器、设置面板和已保存参数。快捷键 `Ctrl+Alt+Shift+G` 在关闭状态仍可打开面板。“恢复原版默认参数”不改变总开关。`mounted` 表示控制器仍在，`active` 表示视觉皮肤启用，加载器分别处理两种状态。

`scripts/install-codex-entry.ps1 -WhatIf` 只输出创建计划。确认采用此入口后执行该脚本，可在桌面创建独立的“Codex 液态玻璃”图标；它隐藏伴随 PowerShell，动态查找当前安装的原生 Codex，自动挂载控制器。安装器拒绝覆盖未知图标，卸载时核验目标、参数和来源记录，只删除自己的两个文件。`-Destination` 可指定已存在目录，`-Action Uninstall -WhatIf` 可查看卸载计划。

这简化了日常启动，但不是原生插件扩展：商店原有普通启动入口没有调试连接时，按钮代码还没加载，无法靠设置中的按钮加载它自己。原生配色导入只提供颜色和字体等字段，不提供动态背景脚本入口。关闭视觉皮肤仍保留这次进程的本机连接；退出再按商店原有入口打开才结束该连接。本次运行验证复用当前应用，没有关闭并重新启动它。

## 使用

在本仓库目录中，先安装开发依赖并构建：

```powershell
pnpm install
pnpm build
```

需要 Node.js 22 或更新版本。以下命令默认只检查已有调试连接，既不启动应用，也不安装皮肤：

```powershell
node scripts/codex-skin.mjs
node scripts/codex-skin.mjs --inspect --port 9223
```

用户明确选择接入并正常完全退出 Codex 后，再在独立 PowerShell 窗口运行：

```powershell
powershell -NoProfile -File .\scripts\start-codex-skin.ps1
```

它会查找当前生产版安装路径，检查是否有同一程序的进程及端口冲突，再用原程序和原生产版配置启动：

```text
ChatGPT.exe --remote-debugging-port=9223 --remote-debugging-address=127.0.0.1
```

启动器不修改安装包、`app.asar`、用户配置、环境变量或登录资料，也不切换 `BUILD_FLAVOR`。它调用统一加载器，主窗口发现、连接、DOM 就绪与最终界面验证各使用 20 秒的等待上限。只有头像浮窗就绪时继续等待真正的主窗口；多个主窗口仍会立即拒绝，不会任意选一个。玻璃和鼠标光影绘制在独立底层，不为原节点增加边框、滤镜或变换；仅在皮肤启用时统一侧栏及实际输入表面的圆角，关闭恢复原生样式。皮肤参数只写入自己的 `codex.glass.skin.v1` 设置键。

找到主窗口后，只要 `document.head` 与 `document.body` 已存在，加载器就安装皮肤样式、背景及界面观察器，不再等完整页面和聊天区域全部出现。后续主界面挂载会被观察器适配；加载器最终仍检查控制器已挂载且真正的 `main` 区域有匹配，缺少匹配时清理本次安装，不把只有全局对象当作成功。这个调整缩短了加载器自己的等待；应用进程启动和调试连接出现仍有耗时，因此没有零闪屏保证。

首次显示鲨鱼时播放 900ms 的爆散和聚合，切换到不同的非空聊天标识时重播。GPU 提前编译着色器、上传固定点位，后续动画只改参数、每帧整批绘制，上限为每秒 60 帧；静止时显示缓存位图。聊天区域短暂消失时保留未完成的开场，区域恢复后重新播放该开场，完成后的同一聊天恢复不会重复开场。减少动画模式跳过聚合；GPU 不可用时使用有限时长、限速的 Canvas2D 降级动画。这些优化限制了皮肤绘制工作量，不能代替全部原生聊天导航的流畅性验证。

界面观察器缓存已找到的原生节点，无关正文的样式变化不再查询整个消息子树；前台多个变更批次合并到一帧。窗口隐藏时仍及时清理，节点消失或选择器改变时重新发现，减少导航期间重复扫描。

已经由用户手动打开调试端口时，可以分别使用：

```powershell
node scripts/codex-skin.mjs --apply --port 9223
node scripts/codex-skin.mjs --remove --port 9223
```

`--apply` 只读本仓库的 `dist/codex-glass.runtime.js` 并在主界面执行；`--remove` 调用它的 `dispose()` 并核验全局句柄已移除。加载器只接受同一回环端口的一个 `type: page`、URL 为 `app://-/index.html` 的主窗口目标，并排除 `initialRoute=/avatar-overlay`、`/detached-window` 辅助路由；多个主窗口、普通网站、内嵌浏览器、预览页和 iframe 都会被排除或拒绝。只有 `--apply` 会等待主窗口出现；检查和移除不等待启动，也不会重复执行超时的挂载操作。返回内容只有目标 ID、应用 URL、运行时版本及皮肤状态，不读取聊天内容、密钥或浏览器存储。

## 回退与连接边界

临时调试端口会让本机能连接它的程序检查和控制应用界面。只在本机测试时开启，不把它绑定到外部地址，不转发端口。测试结束后先执行 `--remove`，再正常退出 Codex，按平时的方式打开；普通启动不附带本次调试参数。加载器每条命令执行完就断开连接。

冷启动期间，主页面切换可能让一次就绪检查暂时失效。加载器现在会在原有等待上限内重新检查同一个主窗口，只处理明确的执行上下文切换错误；主窗口改变、多个主窗口或其他异常仍停止处理。这个等待发生在皮肤执行之前，实际挂载只执行一次。

如果执行超时，脚本会把结果标为未知，再做一次仅查询皮肤状态的核验，不自动重试加载或移除。先看核验结果，避免重复操作。网页刷新或应用更新会清掉临时注入，新的版本也可能改变 DOM，需要重新核验适配。

桌面入口隐藏伴随 PowerShell，加载失败时会把加载器的具体原因显示在弹窗中，并将其已脱敏输出保存到 `%LOCALAPPDATA%\CodexLiquidGlass\logs` 下的独立诊断文件。日志只包含加载器输出和退出码，不记录聊天、环境变量或其他应用资料。“保留 Codex 运行”表示加载器没有关闭已经启动的应用，并不表示启动前后台没有退出。结果未知时弹窗明确要求先查询状态，不把超时当成已失败，也不会自动再启动或再次挂载。

本机运行时启用了 ASAR 完整性校验及只从 ASAR 加载应用的保护。直接修改安装资源可能导致签名或完整性失效、启动失败，也会被升级覆盖；本实现不使用这条路线。

## 当前适配依据

以下选择器已在当前真实主窗口核验；设置卡片另外通过本地设置页示例检查：

- 根节点：`#root` 与 `[data-app-shell-frame]`。
- 左侧栏：`aside[data-app-shell-left-panel-appearance]`、`[data-slate-sidebar-content]`。
- 主内容：`main[data-app-shell-main-surface="default"]`。
- Codex 输入框：`[data-codex-composer-root]`；实际玻璃表面使用它里面的 `[data-composer-surface-variant]`，不覆盖外层的变更提示和状态区域。
- 输入框样式变量：`--composer-layout-surface-background`、`--composer-layout-surface-backdrop-filter`、`--composer-layout-surface-shadow`。

背景适配还处理原生页面和底部遮罩使用的颜色变量，避免设置页及输入区出现整块白底。后续版本兼容仍需重新核验；当前运行记录只覆盖所列窗口、页面和操作，不代表全部页面及聊天功能均已测试。
